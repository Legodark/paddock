# Paddock: source architecture and scope

Reviewed source: `5e8091b6fb8a88ec4c4550b9356dd7026d44b42e`, clean at start. Scoped standard audit of `web/`, `deploy/vercel/`, `tools/`, `ci/`, `.github/workflows/`, and `security/`. No compatible prior coverage ledger or findings JSON exists; earlier Paddock prose and CI evidence inform priorities, never assumed coverage. Historical Flutter/backend and training notebooks are context only, not a maintained deployment or an execution target. No useful external comparable baseline is grounded in local documentation.

Paddock is a historical 2023 vehicle-price demonstration. A visitor supplies vehicle features, obtains a frozen-forest prediction and historical comparables, or enters text for a frozen binary intent classifier and deterministic car filters. It is not a generative LLM or tool-calling agent. Public catalog scope remains an owner decision; a common read-only catalog, not a tenant/owner data model, is intentional. The API source has no application session, account mutation, payment, privileged chatbot action, or tenant identity. Do not report intended common catalog reads as an authorization bypass.

React/TypeScript/Vite renders the web app; `web/src/api.ts` sends same-origin requests with same-origin credentials, timeout, AbortController and response-shape checks. Forms use `vehicle.ts`; `CatalogChat.tsx` caps text/history and requires user-intent confirmation for some reads, not server authorization. `chat-interpreter.ts` maps bounded text and escaped category aliases to fixed filters. Network response text, vehicle labels and chat history enter React text nodes; brand image URLs come from a committed mapping. Navigation is fixed anchors/static links. No in-scope service worker, postMessage, browser account store, WebSocket, broker or local IPC was identified.

`deploy/vercel/api/index.py` constructs Flask. Six `/api/v1` routes expose health, prediction catalog, prediction, search catalog, classification and car search. `paddock_service/app.py` sets a 16 KiB body limit, a 2048-byte raw query limit, exact JSON keys, categorical whitelists, finite numeric envelopes, brand/model consistency, fixed SQL columns/operators, parameterized values and at most ten result rows. SQLite opens read-only/immutable/query-only. Responses use no-store and restrictive headers; unexpected errors return generic text and log only exception type. Inspect direct and error paths, not just frontend-constrained calls.

Lazy initialization under a lock reads deployment-selected assets, verifies the exact manifest file set, sizes/hashes and source-pinned compact model digests, then loads a read-only mmap price forest, capped gzip/JSON classifier and SQLite. Runtime does not load pickle. `forest.py` checks shapes, finite values, feature indices and forward child offsets. Paths and manifest files are operator/deployment inputs, not HTTP-selected files. Conversion executes historical pickle only after source-pinned checks in a distinct local tool; same-principal maintainer authority is not a privilege boundary.

`tools/prepare_vercel_package.py` verifies frozen inputs and separates `public/` from private `assets/`; `build_vercel_package.cjs` invokes the official builder and materializes files; `check_vercel_package.py` inspects outputs and executes a local WSGI check. Other tools convert artwork, validate a local firewall proposal, or act through an operator's GitHub CLI. The latter must not be invoked in this audit.

The CI workflow uses pull_request/push/manual/schedule, contents:read, pinned actions and nonpersisted checkout credentials; it does not deploy. `ci/check.sh` fetches runtimes, packages, browsers and vulnerability data, so the entire entry point is prohibited here. Existing standard-library/Flask dummy fixtures may be used only after a complete parent-approved sandbox is ready; no installs, historical conversion or production data execution. Tool paths and native dependency outputs deserve source review.

Source `vercel.json` selects public static output, a Python WSGI function with private assets and a 10-second per-request limit, `/api` rewrites and security headers. The local firewall declaration proposes a project/IP/region rate limit; it is not live enforcement evidence. Provider access protection, routing, counters, billing, CPU/RAM and release/rollback attachments are separate platform facts, not inferred by this audit. Outside-source uncertainty alone is not a vulnerability without a concrete source-grounded failed invariant.

Selected companions: CLIENT-SIDE for service data to DOM/navigation; WEB-PROTOCOL-AND-AUTH for source header/cache/proxy handoffs; CLOUD-AND-DEPLOYMENT for static/function/config isolation; SUPPLY-CHAIN-AND-RELEASE for dependency/build/CI authority and artifact identity; RESOURCE-EXHAUSTION-AND-AVAILABILITY for bounded parsing/inference/SQL, shared quotas, cancellation and recovery. Excluded native memory, federated identity, tenant lifecycle, RPC/broker, mobile/IPC and LLM agent domains lack their required in-scope boundaries. No source edits or external/shared-service calls are allowed. Only the parent may retain/promote files and update shared audit records.
